## User Scenarios & Testing *(mandatory)*

### User Story 1 - 维护类目树并用于前台展示 (Priority: P1)

商品运营在后台维护多层级类目树（新增/编辑/启停/排序/迁移层级），前台（含 miniapp）可以获取“可展示的类目树”，并基于类目进行商品筛选与导航。

**Why this priority**: 类目是商品信息架构的基础；没有可用的类目树就无法在前台形成可导航的商品展示与筛选体验。

**Independent Test**: 仅实现本用户故事即可完成“后台可维护 + 前台可读取”的最小闭环，并可被独立验收。

**Acceptance Scenarios**:

1. **Given** 系统内无类目，**When** 商品运营创建根类目与子类目并保存，**Then** 后台类目树应能展示正确的层级、名称与顺序。
2. **Given** 某个类目被停用，**When** 前台请求“可展示类目树”，**Then** 停用类目及其整棵子树都不应出现在可展示结果中。
3. **Given** 现有类目树存在多个兄弟节点，**When** 商品运营调整同级排序或迁移类目到新的父节点，**Then** 后台与前台获取到的树结构应反映最新层级与排序且不出现环。
4. **Given** 某类目下存在已关联的商品，**When** 商品运营尝试删除该类目，**Then** 系统应阻止删除并提示原因（应通过迁移/停用等方式处理）。

---

### User Story 2 - 配置类目模板并驱动商品录入校验 (Priority: P2)

商品运营为类目配置“类目模板”（字段分组、字段类型、必填/校验规则、默认值、多语言、继承），在创建/编辑商品时，系统可根据所选类目提供模板定义用于表单渲染与校验，并能进行预览/模拟填报验证模板配置质量。

**Why this priority**: 模板是保证商品录入质量与合规的关键；它把“类目”与“录入校验”连接起来，避免不同运营人员填写不一致。

**Independent Test**: 仅实现模板管理与商品录入侧的模板读取/校验，即可独立演示“选类目→得到模板→按规则校验”的价值链。

**Acceptance Scenarios**:

1. **Given** 某类目已绑定模板，**When** 运营人员在商品录入时选择该类目，**Then** 系统应返回模板字段定义并对提交数据执行必填与规则校验。
2. **Given** 子类目未显式绑定模板，**When** 选择该子类目进行录入，**Then** 系统应自动继承最近祖先的“已发布模板”用于录入与校验。
3. **Given** 模板支持多语言字段，**When** 切换语言查看模板字段，**Then** 字段名称/描述应匹配对应语言（缺失时按约定回退到默认语言）。
4. **Given** 子类目显式绑定了自己的模板，**When** 选择该子类目进行录入，**Then** 系统应仅使用子类目的模板进行校验（完全覆盖祖先模板，不做字段合并）。

---

### User Story 3 - 管理渠道类目映射与批量处理 (Priority: P3)

渠道运营为不同渠道/平台配置类目映射（平台类目 ID、映射策略、同步状态），并支持批量导入/导出与变更审计，确保商品上架与同步策略可以基于类目映射稳定执行。

**Why this priority**: 当存在多渠道经营时，类目映射是商品上架与同步的前置条件；缺少映射会导致渠道侧类目不一致、同步失败或人工成本上升。

**Independent Test**: 仅实现映射增删改查 + 查询 + 导入导出（任一格式）即可独立验证“渠道映射可维护、可追踪、可批量化”。

**Acceptance Scenarios**:

1. **Given** 某类目尚无任何渠道映射，**When** 渠道运营新增一个渠道映射并保存，**Then** 再次查询该类目映射应返回刚创建的记录且可被编辑/删除。
2. **Given** 已存在映射记录，**When** 执行批量导入并包含同一渠道同一平台类目 ID 的重复映射，**Then** 系统应拒绝冲突并给出可定位的错误信息（指明冲突项）。
3. **Given** 映射发生变更，**When** 查询审计记录，**Then** 应能看到变更前后摘要、操作者与时间戳。

---

### Edge Cases

- 类目迁移导致形成父子循环（环）时应如何处理（必须被阻止）。
- 同一父节点下出现重复“编码/别名/展示名称”时应如何处理（需有明确唯一性规则与错误提示）。
- 类目被停用但仍被商品引用时，商品在前台的展示/筛选行为如何定义（已明确：停用类目及其子树不出现在“可展示类目树”；商品展示/筛选仍需在实现阶段补充一致性规则）。
- 类目模板发布后，已存在商品的校验与编辑策略如何定义（已明确：只影响新建/编辑时校验；需要提供影响范围预览与批量重检任务）。
- 批量迁移/批量停用/批量导入导出过程中部分失败的处理方式（部分成功 vs 全部回滚、错误报告）。

## Requirements *(mandatory)*

### Assumptions

- 类目、模板、映射与权限均为“租户隔离”的业务数据。
- 类目树层级上限默认为“支持多层级”，但需要在产品上定义建议上限与性能基线（见成功指标）。
- 删除属于高风险操作：默认不允许删除存在子类目或已被商品引用的类目，推荐通过停用与迁移处理。

### Functional Requirements

- **FR-001**: 系统 MUST 支持创建、编辑、查看多层级类目，并维护父子层级关系与展示顺序。
- **FR-002**: 系统 MUST 提供“类目树查询”能力，至少支持按名称/编码/状态过滤，并能返回层级结构与必要展示字段。
- **FR-003**: 系统 MUST 支持类目的启用/停用，并使“可展示类目树”只包含可用类目（停用类目及其整棵子树不返回）。
- **FR-004**: 系统 MUST 支持类目的排序调整与层级迁移，并保证迁移不会产生父子循环。
- **FR-005**: 系统 MUST 定义并执行类目唯一性规则（租户内 code 全局唯一；同父节点下 displayName 唯一；alias/slug 全局唯一），违规时返回可定位错误。
- **FR-006**: 系统 MUST 阻止删除存在子类目或已被商品引用的类目，并返回明确原因与建议操作（迁移/停用）。
- **FR-007**: 系统 MUST 支持类目多语言信息的维护与读取，并定义缺失语言时的回退策略。
- **FR-008**: 系统 MUST 支持为类目绑定一个可生效的类目模板，并定义模板的继承与覆盖规则（子类目未绑定时继承最近祖先已发布模板；子类目绑定模板后完全覆盖，不做字段合并）。
- **FR-009**: 系统 MUST 支持类目模板的创建、编辑、启用/停用与版本化发布，并保留历史版本用于回滚。
- **FR-010**: 系统 MUST 在商品录入/编辑场景中，根据所选类目返回可用模板定义，并对录入数据执行模板校验（必填、类型、规则）。
- **FR-011**: 系统 MUST 支持模板预览/模拟填报验证，以便运营在发布前发现配置错误。
- **FR-011A**: 系统 MUST 在模板发布/回滚后提供“影响范围预览”，并提供对受影响商品执行“批量重检”的能力（发布/回滚不应自动改变存量商品状态）。
- **FR-011B**: 系统 MUST 支持在品类上维护“销售规格模板”（规格维度与允许取值），用于沉淀同品类 SPU 可复用的 SKU 变体规格；SPU 创建/编辑时可显式同步并裁剪，不得静默覆盖已启用规格。
- **FR-012**: 系统 MUST 支持为类目配置多渠道类目映射，并可查询某类目的全部映射记录。
- **FR-013**: 系统 MUST 支持渠道映射的批量导入与导出（CSV），并对冲突/非法数据提供可定位的错误报告。
- **FR-014**: 系统 MUST 支持按角色/组织设置“可管理的类目范围”，并对关键操作执行权限校验（读取、管理、模板、映射、导入导出）。
- **FR-015**: 系统 MUST 记录类目 CRUD、模板编辑/发布/回滚、渠道映射变更、批量任务与导入导出等审计事件，并可按类目查询最近变更。

### 销售规格模板业务说明

品类销售规格模板用于回答：“这一类商品通常有哪些可售规格？”

它不是某个具体商品的 SKU，也不会直接生成库存。它的作用是给同品类 SPU 提供统一、可复用的规格来源，减少重复录入和命名漂移。

示例：

```text
品类：T 恤
  销售规格模板：
    颜色：黑色、白色、灰色
    尺码：S、M、L、XL

SPU：基础款纯棉 T 恤
  从品类同步后实际启用：
    颜色：黑色、白色
    尺码：S、M、L

最终 SKU：
  黑色 / S
  黑色 / M
  黑色 / L
  白色 / S
  白色 / M
  白色 / L
```

关键规则：

- 品类模板定义标准规格，SPU 必须显式同步后才会使用。
- 同步动作只把模板复制到 SPU 规格定义里，不会静默覆盖已保存规格。
- SKU 生成器只读取 SPU 实际启用规格，不直接读取品类模板。

### Key Entities *(include if feature involves data)*

- **商品类目 (Product Category)**: 表示一个可用于商品归类与展示的节点，包含父子关系、排序、启停状态、编码/别名、SEO/展示字段、绑定模板等。
- **类目多语言信息 (Category Locale)**: 表示类目在不同语言下的名称与描述等可展示字段。
- **类目模板 (Category Template)**: 表示一套可复用的字段与校验规则定义，可绑定到类目并支持继承/覆盖。
- **模板字段 (Template Field)**: 表示模板中的字段定义（分组、类型、是否必填、校验规则、默认值、多语言支持、是否可继承）。
- **模板版本 (Template Version)**: 表示模板在某次发布后的不可变快照，用于回滚与影响范围追踪。
- **品类销售规格模板 (Category Sale Spec Template)**: 表示某品类下可复用的销售规格维度与允许取值，例如“尺寸/体型/工艺”，用于 SPU 规格初始化与 SKU 组合规范化。
- **渠道类目映射 (Category Mapping)**: 表示某类目与某渠道/平台类目之间的映射关系与同步状态。
- **类目权限范围 (Category Permission Scope)**: 表示某角色/组织可读取或可管理的类目集合/范围。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 运营人员可以在 ≤ 2 分钟内完成“创建一个两级类目 + 调整排序 + 绑定模板”的基础操作，并在保存后立即可见。
- **SC-002**: 在 5,000 个类目节点规模下，类目树查询在正常负载下的响应时间 P95 ≤ 500ms（可按环境基线调整，但需有明确目标）。
- **SC-003**: 商品录入场景中，模板校验失败时 100% 能定位到具体字段并给出可理解的错误信息（可用于前端直接展示）。
- **SC-004**: 模板发布错误率 ≤ 1%，且每次发布都支持回滚到上一个已发布版本并在 ≤ 10 分钟内恢复可用。
- **SC-005**: 渠道映射完整率 ≥ 95%（针对“重点渠道”集合），并可通过报表/查询核验。
- **SC-006**: 批量导入任务成功率 ≥ 99%，失败时必须产出可下载/可复制的失败清单以便修复重试。
