# Features Test Guides

本目录存放跨端到端业务场景的测试指导文档，面向 QA、研发和运营。每份文档需回答三类问题：

1. **场景背景**：业务目标、依赖模块、需要预置的数据或 RBAC 权限。
2. **验证路径**：如何在系统 UI/API 中执行该能力，包括关键导航、表单字段、后台任务、审批或自动化流程。
3. **回归策略**：可复用的测试数据、脚本或代码入口（如 E2E/集成测试文件、Postman/Thunder Client Collection、make 目标等）。

## 目录结构

- `README.md`（本文）：约定文档格式及维护指引。
- `inventory/sku_stock_mvp.md`：SKU 可用库存闭环与上架/发布库存门禁（MVP）。
- `membership/membership_entitlements_onboarding.md`：订阅支付后会籍/权益/代币发放与幂等验证用例。
- `product/subscription_onboarding.md`：订阅型商品上架 & 下单准备的完整用例。
- `product/standard_onboarding.md`：常规一次性商品上架与库存准备用例。
- `product/category_management.md`：商品类目使用指导（类目树 / 模板 / 渠道映射 / CSV）。
- _更多场景_：请按 `snake_case` 命名，例如 `channel_resync_runbook.md`。

## 规范约定

| 区块           | 内容说明                                                                                  |
| -------------- | ----------------------------------------------------------------------------------------- |
| 背景与目标     | 引用相关 Spec/Task 或 Issue，说明业务价值与完成标准。                                     |
| 依赖 & 权限    | 必要的 RBAC Scope、配置文件、环境变量或外部服务（如支付/物流沙盒）。                      |
| 测试步骤       | 分步骤罗列操作（UI + API），遇到异步任务需注明轮询/等待方式以及日志/数据库检查点。        |
| 数据准备       | 给出最小可复现的数据集（SQL/命令/表单示例），尽量引用现有 `seed`、`make` 任务或脚本。     |
| 回归测试提示   | 如果已有自动化用例，写明文件路径 / 命令；若尚未实现，描述预期覆盖点，便于后续补齐代码。    |
| 常见故障与排障 | 罗列可能遇到的错误、日志位置以及修复提示（选填）。                                        |

## 维护建议

- **与代码同步**：当 API 契约或 UI 交互调整时，及时更新相关步骤与截图链接。
- **关联自动化**：一旦补充了 Playwright、Vitest、integration-smoke 等脚本，在文档“回归测试提示”处同步命令。
- **版本管理**：如同一场景在不同发行版本存在差异，可用 `### vX.Y` 段落分别标注。

> ✅ 贡献流程：新增或更新文档后，请在 PR 描述中附上对应的测试命令（手动或自动）。如涉及新增种子/脚本，请同步 `docs/plan` 中的发布清单。
