# 营销旅程 & 自动化 PRD

> 计划新增页面：`web-admin/app/pages/market/journey.vue`（待建）及客户模块中的旅程入口。该模块负责基于客户行为/分群自动触发营销动作（发券、推送、积分、任务），支持编排、调度、AB 测试、监控。

## 1. 背景与目标
- 现有系统缺乏自动化营销能力，运营需要手动发券、发送通知、管理分群；无法基于客户行为实时触达。
- 目标是搭建可视化旅程编排器，连接客户数据、营销资产（促销、券、卡、积分）、渠道触达（短信、邮件、站内、Webhook）。

**目标**
1. 提供旅程画布：以节点/连线方式定义触发条件、决策、动作、延时、退出条件。
2. 支持实时触发（事件）、定时触发（批量分群）、AB 测试、旅程版本管理。
3. 监控旅程运行指标：触达人数、转化率、退出率、错误日志。

## 2. 角色
| 角色 | 诉求 |
| --- | --- |
| CRM/运营 | 自助搭建旅程、管理触达策略 |
| 营销/增长 | 结合活动目标、客户分群开展自动化流程 |
| 数据/技术 | 提供事件、属性、API，确保旅程运行稳定 |
| 法务/合规 | 控制触达频率、隐私合规（退订、GDPR） |

## 3. 信息架构
1. **旅程列表**：名称、类型（拉新/激活/留存/召回）、触发方式、状态、目标、负责人、最近发布时间、运行指标。
2. **旅程设计器**
   - 触发节点：事件（注册、下单、退货）、分群（VIP、沉睡）、手动启动。
   - 条件/分支：属性过滤、行为、时间窗口、AB 分流、循环。
   - 动作节点：发送短信/邮件/站内信、发券/礼品卡/积分、调用 Webhook、创建任务、推送到客服。
   - 控制节点：延时、并行、等待事件、退出、限制触达次数。
   - 版本：草稿/测试/发布、复制版本、回滚。
3. **运行监控**
   - 实时指标：进入人数、各节点转化、执行成功/失败、平均延时。
   - 告警：失败、触达超限、黑名单命中。
   - 调度日志：节点执行日志、错误详情、重试。

## 4. 功能清单
| 功能 | 描述 |
| --- | --- |
| 旅程画布 | 拖拽式设计器，支持节点库、连线、缩放、注释 |
| 触发器 | 实时事件、定时任务、手动批量启动、API 调用 |
| 分群 | 引用客户模块分群、动态属性、行为标签 |
| 动作库 | 发券、发积分、发礼品卡、发送消息、更新客户属性、调用 API、创建任务 |
| AB 测试 | 节点级分流，查看版本表现 |
| 频控/退订 | 控制触达频率、尊重退订状态，合规日志 |
| 旅程版本 | 草稿/测试/发布区分，支持沙盒测试、版本比较、回滚 |
| 监控 & 告警 | 实时看板、节点健康、错误告警、重试机制 |

## 5. 流程示例
1. **创建旅程**：选择模板 → 配置触发条件（如“新客注册后 7 天未下单”）→ 添加动作（发券、推送、提醒）→ 设置 AB 测试 → 提交审批/发布。
2. **运行**：旅程发布后，事件流进入触发节点，按连线执行；若节点失败，进入重试或异常处理。
3. **优化**: 根据指标查看各节点表现，调整文案、动作或分支，发布新版本。

## 6. 数据 & API
- 表：`journeys`、`journey_versions`、`journey_nodes`、`journey_edges`、`journey_instances`、`journey_logs`、`journey_metrics`。
- API：
  - `GET/POST /api/journeys`、`PATCH /api/journeys/{id}`、`POST /api/journeys/{id}/publish`、`POST /api/journeys/{id}/archive`。
  - `POST /api/journeys/{id}/trigger`（手动触发）、`GET /api/journeys/{id}/metrics`。
  - Webhook/事件输入：`POST /api/journeys/events`。

## 7. 权限与合规
- 权限：`journey.read`、`journey.manage`、`journey.publish`、`journey.metrics`。
- 合规：记录触达日志、支持用户退订、遵守 GDPR/隐私；敏感数据需脱敏。
- 审计：旅程变更、发布、暂停、触达策略调整均记录。

## 8. KPI
| 指标 | 目标 |
| --- | --- |
| 旅程构建效率 | 新旅程搭建 ≤ 2 天 |
| 节点成功率 | ≥ 99% |
| A/B 分流统计准确度 | 100% |
| 告警响应时间 | < 15 min |

## 9. 风险
- 事件延迟或丢失影响旅程效果，需要可靠事件管道。
- 复杂旅程可能造成循环或爆量，需要防护机制。
- 隐私/频控不当会导致投诉，需严格控制。
