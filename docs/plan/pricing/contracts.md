# 合同价 / 协议价（B2B）PRD

> 覆盖页面：`web-admin/app/pages/pricing/contracts.vue` 以及客户/供应商详情中的合同区块。该模块面向 B2B 场景，为特定客户、合作伙伴提供协议价、返利、账期等条款，并与价目表、结算、库存联动。

## 1. 背景与目标
- 大客户/分销商常通过合同确定定制化价格、返利、付款条件；需在系统内完整管理合同生命周期，并与价格查询、订单、结算系统联动。
- 当前 UI 仅展示合同列表，需要补齐合同条款、价目引用、审批、通知、执行跟踪。
- **场景定位**：该模块面向 2B 业务，合同生命周期需要完整的跟进看板（从草稿、审批、签署、生效、执行到续约/终止）以及留痕变更（版本 diff、审批意见、执行日志），为销售、定价、法务、财务等多角色提供透明协同。

**目标**
1. 建立合同主数据：合同头信息、关联客户/供应商、覆盖 SKU/价目、条款（价格、折扣、返利、账期、起订量等）。
2. 提供审批、版本管理、到期提醒、执行监控，确保合同价与订单/结算一致。
3. 支持从合同生成价目表、定价规则，或反向引用既有 pricebook。

## 2. 角色
| 角色 | 价值 |
| --- | --- |
| 销售 / BD | 创建合同、追踪审批、查看执行情况 |
| 定价经理 | 审核合同中的价格条款、确保符合策略 |
| 财务 / 结算 | 获取账期、返利、发票要求，核算应收应付 |
| 法务 | 审查合同文本、附加条款 |
| 客户成功 | 查看合同权益、提醒续约 |

## 3. 信息架构
1. **合同列表**
   - 字段：合同编号、客户/伙伴、状态（草稿/审批中/生效/到期）、金额、有效期、负责人、关联价目。
   - 筛选：状态、客户、渠道、负责人、到期时间。
2. **合同详情**
   - 基础信息：合同号、类型、客户、签署日期、有效期、附件、审批记录。
   - 条款：价格条款（引用 pricebook 或自定义）、折扣、返利、账期、付款方式、发票要求、交付 SLA、最低采购量、渠道限制。
   - 覆盖范围：SKU/类目/渠道/区域；可绑定 pricebook 版本。
   - 执行监控：订单金额 vs 目标、返利累计、违约情况、任务提醒。
   - 通知：到期提醒、里程碑、审批节点。
3. **合同与价目联动**
   - 契约价可直接生成新的 pricebook 或定价规则；或引用 existing pricebook（锁定版本）。
   - 任何合同价变动需同步到价格查询 API，并通知订单/结算。
4. **合同看板与轨迹**
   - 以 Kanban/Timeline 展示合同在不同阶段（草稿/审批/待签/已签/执行/到期/终止）状态，支持按负责人或客户分组；
   - 留痕变更：每次修改、审批、复核、续约、变更都会记录版本 diff、操作者、时间戳，便于审计。

## 4. 功能清单
| 功能 | 描述 |
| --- | --- |
| 合同模板 | 按客户类型/渠道提供模板，快速创建 |
| 审批流 | 多级审批（销售主管 → 定价 → 财务 → 法务），可配置 SLA |
| 条款编辑 | 支持结构化字段 + 附件；价格可引用 pricebook 或直接录入 |
| 价目引用 | 合同可绑定 pricebook，锁定版本；合同结束自动下线 |
| 执行监控 | 展示订单完成度、返利应付、账期状态；可生成提醒/任务 |
| 到期管理 | 提醒续约、支持复制合同生成新版本 |
| 合同变更 | 可发起变更申请，记录版本 diff、审批、回滚 |
| API & 同步 | 合同价通过 API 暴露给订单、结算；与财务对接账期/返利 |

## 5. 流程
1. **合同创建**
   1. 销售选择客户 → 选择模板 → 填写条款、附上附件/价目引用。
   2. 提交审批 → 各角色审核 → 生效。
   3. 生效后自动生成/更新 pricebook 或规则，订单查询即可使用合同价。
2. **执行与监控**
   1. 系统根据订单/结算数据更新合同 KPI（采购额、返利、账期）。
   2. 超过阈值或违约条件触发提醒。
3. **变更/续约**
   1. 发起变更 → 记录差异 → 审批 → 更新合同与价目。
   2. 到期前自动提醒负责人，复制为新合同版本。

## 6. 数据 & API
- **表**：`pricing_contracts`、`pricing_contract_terms`、`pricing_contract_versions`、`pricing_contract_pricebooks`、`pricing_contract_metrics`、`pricing_contract_audit_logs`。
- **API**：
  - `GET /api/pricing/contracts`、`POST /api/pricing/contracts`、`PATCH /api/pricing/contracts/{id}`、`POST /api/pricing/contracts/{id}/submit`、`POST /api/pricing/contracts/{id}/approve`、`POST /api/pricing/contracts/{id}/renew`。
  - `GET /api/pricing/contracts/{id}/pricebooks`、`POST /api/pricing/contracts/{id}/pricebooks`。
  - `GET /api/pricing/contracts/{id}/metrics`。

## 7. 权限与审计
- 权限：`contract.read`、`contract.manage`、`contract.approval`、`contract.price`、`contract.metrics`。
- 审计：合同创建/变更/审批/发布/终止需写入审计事件，附带条款 diff、审批意见。
- 敏感字段（价格、返利、账期）需权限控制，提供脱敏视图。

## 8. KPI
| 指标 | 目标 |
| --- | --- |
| 合同审批周期 | ≤ 5 个工作日 |
| 合同执行率 | ≥ 90%（订单完成度） |
| 到期提醒覆盖率 | 100% |
| 合同价同步延迟 | < 5 分钟 |

## 9. 依赖与风险
- 依赖客户主数据、价目表、订单、结算、财务系统；需统一客户 ID 与价格 API。
- 合同条款复杂，需结构化 + 非结构化并存；要提供模板和校验。
- 合同价与普通价目同时作用，必须明确优先级（合同价优先）。
- 审批/签署流程可能依赖外部系统（电子签名）。

## 10. Backlog
- 电子签约集成（DocuSign 等）。
- 合同执行仪表盘，与 CRM/销售 pipeline 打通。
- 返利自动计算与结算。
- 多合同叠加策略（如全国合同 + 区域补充协议）。
