# 优惠券 PRD

> 覆盖页面：`web-admin/app/pages/customer/membership/points/mall.vue` 中的券兑换部分、`web-admin/app/pages/market/promotions.vue` 的优惠券卡片，以及未来独立的 `pricing/coupons.vue` 页面。优惠券既属于定价/促销能力，也与会员、积分、渠道联动。
> 当前阶段仅做“订单可关联优惠券”的最小闭环，复杂规则暂不实现，作为后续独立 feature。

## 0. 当前阶段范围（MVP）
- 目标：支持在订单中录入优惠券、提交审核、记录日志；不做自动核销与价格结算。
- 入口：订单详情（后台）新增“添加优惠券”与审核流程；券码校验为最小校验（是否已在审核记录中使用）。
- 不做：模板/批次/库存/领取/发放/叠加引擎/风控/统计/用户端展示。
- 关联数据：订单侧使用审核记录表（`order_benefit_reviews`），作为后续接入券系统的预留口。

## 0.1 已确认的规则需求（后续 feature）
- 适用范围：需要支持门槛与适用范围配置（后续覆盖全店/指定 SPU/指定 SKU/指定类目/渠道/客户等）。
- 使用门槛：需要支持订单金额门槛（是否含件数门槛待后续确认）。
- 券码生成：后台生成，支持批量生产（规模待后续确认）。

## 1. 背景与目标
- 需要统一的优惠券中心，支持多种券类型（满减、折扣、现金、包邮、礼品），控制发行、核销、统计，与积分、促销共享库存。
- 目前券配置散落在积分商城，需要抽离为独立模块。
- **与定价层关系**：优惠券属于营销权益层，基于 pricebook/阶梯价等定价结果再做抵扣或折扣。券模板的“适用范围”可引用价目表维度（SKU/渠道/客户组），叠加策略需与定价链路一致，便于计算真实让利成本。

**目标**
1. MVP：订单中可手动录入券码并提交审核，保留日志。
2. 后续：与定价/订单/营销/积分联动，支持发券、兑换、自动发放、第三方渠道同步。
3. 后续：提供实时监控、风控（防薅羊毛）、审批流程。

## 2. 信息架构（未来规划）
1. **优惠券列表**
   - 字段：名称、类型、面值/折扣、门槛、适用范围（SKU/类目/渠道/客户）、库存、状态、有效期、发行批次。
   - 筛选：类型、状态、渠道、活动、客户标签。
2. **优惠券模板 / 详情**
   - 基本信息：名称、描述、标签、可叠加策略、展示文案。
   - 条件：
     - 类型：满减、折扣、现金、包邮、礼品券、兑换券。
     - 使用门槛：订单金额、SKU、类目、渠道、客户组。
     - 时间：有效期、领取期。
     - 限制：每人限领、是否可转赠、是否可叠加、是否需要验证码。
   - 发放渠道：手动发放、自动触发、积分兑换、API、第三方渠道。
   - 核销规则：订单匹配方式、优先级、与其他促销叠加。
3. **批次与库存**
   - 发行批次：数量、渠道、成本、审批。
   - 库存管理：冻结、作废、恢复。
4. **监控与报表**
   - 券领取、使用、核销率、GMV 贡献、ROI、异常情况。

## 3. 功能清单（未来规划）
| 功能 | 描述 |
| --- | --- |
| 券模板 & 批次 | 模板定义 + 多批次发行；批次可继承模板属性 |
| 发放方式 | 手动发放、自动触发（事件/规则）、积分兑换、API 发放、渠道同步 |
| 核销引擎 | 下单时根据优先级选择最优券；支持多券叠加/排他、券包 |
| 风控 | 限定 IP、设备、频率，识别批量领券；黑名单 |
| 审批 | 大额券、特殊客户需审批；记录成本、预算 |
| 通知 | 发放/即将过期提醒、短信/邮件/站内信 |
| 统计 | 实时监控领取/使用、GMV、ROI、客户留存 |
| API | `POST /api/coupons/issue`、`POST /api/coupons/redeem`、`GET /api/coupons/user` 等 |

## 4. 流程示例（未来规划）
1. **创建券模板** → 定义类型、条件、叠加策略 → 提交审批。
2. **发行批次** → 指定数量、渠道、预算 → 审批 → 推送到渠道或待领取池。
3. **发放** → 手动/自动/积分兑换/API → 用户收到券，状态为未使用。
4. **核销** → 下单时匹配可用券 → 应用折扣 → 更新状态，记录订单 ID。
5. **统计 & 风控** → 监控使用情况，异常行为触发告警或封禁。

## 5. 数据 & API
### 当前阶段（MVP）
- **表**：`order_benefit_reviews`（订单侧审核记录）。
- **API**：
  - `GET /admin/orders/:id/benefit-reviews`
  - `POST /admin/orders/:id/benefit-reviews`
  - `POST /admin/orders/benefit-reviews/approve`
  - `POST /admin/orders/benefit-reviews/reject`
  - `GET /admin/orders/benefit-codes`（最小校验，后续接券系统）
### 未来规划
- **表**：`coupon_templates`、`coupon_batches`、`coupons`（实例）、`coupon_rules`、`coupon_redemptions`、`coupon_audit_logs`、`coupon_stats`。
- **API**：
  - `GET /api/coupons/templates`、`POST /api/coupons/templates`、`PATCH /api/coupons/templates/{id}`。
  - `POST /api/coupons/templates/{id}/batches`、`POST /api/coupons/batches/{id}/issue`。
  - `POST /api/coupons/issue`、`POST /api/coupons/redeem`、`GET /api/coupons/user`、`GET /api/coupons/stats`。

## 6. 权限与审计
- 权限：`coupon.read`、`coupon.manage`、`coupon.issue`、`coupon.approval`、`coupon.stats`。
- 审计：模板、批次、发放、作废、批量操作均记录，并可追踪发放来源（积分兑换、营销活动等）。
> MVP 仅使用订单审核权限与事件日志记录。

## 7. KPI（未来规划）
| 指标 | 目标 |
| --- | --- |
| 核销率 | ≥ 30%（视活动类型） |
| 异常拦截率 | ≥ 95% |
| 发放延迟 | < 1 分钟 |
| 审批周期 | ≤ 1 天 |

## 8. 风险（未来规划）
- 大量领券/薅羊毛，需要风控与频控。
- 与其他促销叠加导致亏损，需要优先级和预算控制。
- 渠道差异（第三方平台 API）需适配。

## 9. Backlog
- 券包/权益组：组合多个券一起发放。
- 与 CRM 旅程联动：自动触发发券。
- 与礼品卡/积分互换：券与其他权益兑换。
- 区块链/电子发票场景（可选）。
