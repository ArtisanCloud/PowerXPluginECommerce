# 优惠券 PRD

> 覆盖页面：`web-admin/app/pages/customer/membership/points/mall.vue` 中的券兑换部分、`web-admin/app/pages/market/promotions.vue` 的优惠券卡片，以及未来独立的 `pricing/coupons.vue` 页面。优惠券既属于定价/促销能力，也与会员、积分、渠道联动。
> 当前阶段仅做“订单可关联优惠券”的最小闭环，复杂规则暂不实现，作为后续独立 feature。

## 0. 当前阶段范围（MVP）
- 目标：支持在订单中录入优惠券、提交审核、记录日志；不做自动核销与价格结算。
- 入口：订单详情（后台）新增“添加优惠券”与审核流程；券码校验为最小校验（是否已在审核记录中使用）。
- 不做：模板/批次/库存/领取/发放/叠加引擎/风控/统计/用户端展示。
- 关联数据：订单侧使用审核记录表（`order_benefit_reviews`），作为后续接入券系统的预留口。

## 0.1 已确认的规则需求（后续 feature）
- 适用范围：需要支持门槛与适用范围配置（后续覆盖全店/指定 SPU/指定 SKU/指定类目/渠道/客户等）。
- 使用门槛：需要支持订单金额门槛（是否含件数门槛待后续确认）。
- 券码生成：后台生成，支持批量生产（规模待后续确认）。

## 1. 背景与目标
- 需要统一的优惠券中心，支持多种券类型（满减、折扣、现金、包邮、礼品），控制发行、核销、统计，与积分、促销共享库存。
- 目前券配置散落在积分商城，需要抽离为独立模块。
- **与定价层关系**：优惠券属于营销权益层，基于 pricebook/阶梯价等定价结果再做抵扣或折扣。券模板的“适用范围”可引用价目表维度（SKU/渠道/客户组），叠加策略需与定价链路一致，便于计算真实让利成本。

**目标**
1. MVP：订单中可手动录入券码并提交审核，保留日志。
2. 后续：与定价/订单/营销/积分联动，支持发券、兑换、自动发放、第三方渠道同步。
3. 后续：提供实时监控、风控（防薅羊毛）、审批流程。

## 2. 信息架构（未来规划）
1. **优惠券列表**
   - 字段：名称、类型、面值/折扣、门槛、适用范围（SKU/类目/渠道/客户）、库存、状态、有效期、发行批次。
   - 筛选：类型、状态、渠道、活动、客户标签。
2. **优惠券模板 / 详情**
   - 基本信息：名称、描述、标签、可叠加策略、展示文案。
   - 条件：
     - 类型：满减、折扣、现金、包邮、礼品券、兑换券。
     - 使用门槛：订单金额、SKU、类目、渠道、客户组。
     - 时间：有效期、领取期。
     - 限制：每人限领、是否可转赠、是否可叠加、是否需要验证码。
   - 发放渠道：手动发放、自动触发、积分兑换、API、第三方渠道。
   - 核销规则：订单匹配方式、优先级、与其他促销叠加。
3. **批次与库存**
   - 发行批次：数量、渠道、成本、审批。
   - 库存管理：冻结、作废、恢复。
4. **监控与报表**
   - 券领取、使用、核销率、GMV 贡献、ROI、异常情况。

## 4. 流程示例（未来规划）
1. **创建券模板** → 定义类型、条件、叠加策略 → 提交审批。
2. **发行批次** → 指定数量、渠道、预算 → 审批 → 推送到渠道或待领取池。
3. **发放** → 手动/自动/积分兑换/API → 用户收到券，状态为未使用。
4. **核销** → 下单时匹配可用券 → 应用折扣 → 更新状态，记录订单 ID。
5. **统计 & 风控** → 监控使用情况，异常行为触发告警或封禁。

## 9. 完整优惠券机制实施计划（对齐执行版）

> 本章节用于承接“从当前 MVP 审核记录能力，升级到完整优惠券闭环”的执行方案。以下内容优先作为实施依据，若与前文“未来规划”存在粒度差异，以本章节为准。

### 9.1 已锁定业务决策
- 计算时机：**下单结算时最终计算**（商品详情/购物车可做预估，但订单结算复算为准）。
- 叠加策略：**按券模板配置叠加**（可叠加、互斥组、优先级、上限均模板化）。
- 核销时点：**支付成功后核销**（提交订单仅预占，不立即消耗）。

### 9.2 价格计算口径（统一定义）
- 分层模型：
  - 基础价层：`pricebook` 产出 `base_total`。
  - 优惠层：优惠券引擎产出 `discount_total`。
  - 应付层：`payable_total = base_total + shipping + tax - discount_total`，下限为 `0`。
- 一致性要求：
  - 结算页展示可预估，但下单提交必须服务端复算。
  - 订单写入 `pricing_breakdown` 快照，后续模板变更不影响历史订单。

### 9.3 状态机与生命周期
- 用户券资产状态：`available -> reserved -> redeemed`。
- 取消/超时未支付：`reserved -> available`（自动释放）。
- 退款后（按模板策略）：`redeemed -> refunded`（可配置返券或不返券）。
- 并发约束：同一券同一时刻只能被一个进行中订单预占。

### 9.4 分阶段实施（建议 5 个阶段）
1. **Phase A：数据模型与约束**
- 新增表：`coupon_templates`、`coupon_user_assets`、`coupon_usage_logs`、`order_coupon_snapshots`。
- 订单扩展：`coupon_discount_total`、`discount_total`、`pricing_breakdown`。
- 索引与约束：资产状态索引、`(asset_id, order_id)` 唯一约束、核销幂等键。

2. **Phase B：优惠券域服务**
- 能力：模板 CRUD、发券、资产查询、验券试算、预占、释放、核销、退款回补。
- 规则：门槛、范围、有效期、叠加、互斥、优先级、用户限领、发行上限。
- 事件：`coupon.reserved`、`coupon.released`、`coupon.redeemed`、`coupon.refunded`。

3. **Phase C：订单与支付集成**
- 下单：接收 `coupon_ids`，执行“复算 + 预占”并落快照。
- 取消：自动释放预占券。
- 支付成功回调：执行核销，重复回调幂等处理。
- 退款：按模板策略触发返券/不返券。

4. **Phase D：管理端与交易端页面**
- 管理端：模板管理、发券、券资产、核销流水。
- 交易端：可用券选择、最佳优惠推荐、优惠明细、订单优惠快照展示。

5. **Phase E：监控与对账**
- 指标：验券成功率、预占转核销率、释放率、券成本、异常重试率。
- 告警：支付成功未核销、超时未释放、重复核销冲突、金额对账差异。

### 9.5 接口与契约（执行最小集）
- 交易接口：
  - `POST /api/v1/coupons/quote`：订单草稿试算（返回可用券与减免明细）。
  - `POST /api/v1/orders`：新增 `coupon_ids[]` 入参，返回 `pricing_breakdown`。
- 管理接口：
  - `POST /api/v1/admin/coupons/templates`
  - `POST /api/v1/admin/coupons/issue`
  - `GET /api/v1/admin/coupons/assets`
  - `GET /api/v1/admin/coupons/usages`
- 支付联动：
  - 在既有支付回调链路增加“券核销服务调用 + 幂等防重”。

### 9.6 测试与验收清单
- 规则正确性：固定减、比例减、门槛、范围、互斥组、叠加优先级。
- 并发一致性：同券并发下单仅一次预占成功。
- 幂等：支付回调重复投递只核销一次。
- 回归：不传券时订单金额逻辑与当前实现一致。
- 对账：订单快照金额、券流水、支付金额三方一致。

### 9.7 里程碑验收标准
- M1（域能力）：完成模板+资产+试算，接口可用。
- M2（交易闭环）：完成下单预占、取消释放、支付核销。
- M3（运营闭环）：管理端可配置、可追踪、可对账。
