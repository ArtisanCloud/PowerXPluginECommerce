# 礼品卡 PRD

> 覆盖页面：未来的 `pricing/giftcards.vue`（待新增），以及积分商城、促销、订单中的礼品卡引用。礼品卡作为储值型权益，需要统一的发行、充值、消费、结算能力。
> 当前阶段仅做“订单可关联礼品卡”的最小闭环，复杂规则暂不实现，作为后续独立 feature。

## 0. 当前阶段范围（MVP）
- 目标：支持在订单中录入礼品卡、提交审核、记录日志；不做余额扣减与结算。
- 入口：订单详情（后台）新增“添加礼品卡”与审核流程；卡号校验为最小校验（是否已在审核记录中使用）。
- 不做：模板/批次/卡池/充值/核销/对账/风控/统计/用户端展示。
- 关联数据：订单侧使用审核记录表（`order_benefit_reviews`），作为后续接入礼品卡系统的预留口。

## 0.1 已确认的规则需求（后续 feature）
- 抵扣方式：允许部分抵扣（余额可大于订单金额，按实际订单金额扣减）。
- 使用门槛：需要支持订单金额门槛（是否含件数门槛待后续确认）。
- 卡号生成：后台生成，支持批量生产（规模待后续确认）。

## 1. 背景与目标
- 现有系统仅在积分商城中以静态示例展示礼品卡，缺乏完整的卡池管理、发行、充值、消费、对账流程。
- 需要一个可配置、可扩展的礼品卡中心，支持实体卡、虚拟卡、批量发放、第三方渠道对接。
- **与定价/营销关系**：礼品卡作为储值/支付工具，通常在 pricebook/阶梯价/促销/优惠券计算出“应付金额”后参与抵扣；需要定义礼品卡与优惠券/积分的叠加顺序和规则，确保让利逻辑清晰、可追溯。

**目标**
1. MVP：订单中可手动录入礼品卡并提交审核，保留日志。
2. 后续：与订单、积分、优惠券、促销联动，支持作为支付工具或兑换权益。
3. 后续：提供对账、风险控制、审计能力。

## 2. 信息架构（未来规划）
1. **礼品卡模板**
   - 定义卡类型（储值/折扣/权益）、面额、可充值性、有效期、使用渠道、限制（客户组、订单类型）。
   - 绑定品牌/活动、设计、说明、条款。
2. **卡池 / 批次**
   - 批量生成卡号（虚拟或实体），包含卡密、二维码、状态、渠道、库存。
   - 支持导入已有卡号、与第三方卡系统对接。
3. **卡实例**
   - 字段：卡号、卡密、余额、币种、状态、绑定客户、来源（活动/采购）、激活时间、过期时间、渠道。
   - 操作：充值、转赠、冻结、作废、退款。
4. **交易与对账**
   - 每次使用、充值生成交易记录；支持导出对账、对接财务系统。
   - 监控异常（频繁充值/消费、跨区域使用）。

## 3. 功能清单（未来规划）
| 功能 | 描述 |
| --- | --- |
| 模板 & 批次管理 | 创建模板、生成批次、设置发行量、渠道、成本、审批 |
| 激活/充值 | 卡可设置激活机制（订单触发/手工/批量），支持充值、部分退款 |
| 绑定与转赠 | 可绑定到客户账号，也可通过卡号使用；支持转赠并记录轨迹 |
| 消费核销 | 订单支付时选择礼品卡，扣减余额；支持多卡叠加、与券/积分组合 |
| 风控 | 限制单日使用、IP/设备、防洗钱、黑名单 |
| 通知 | 激活、充值、即将到期提醒 |
| API | `POST /api/giftcards/issue`、`POST /api/giftcards/redeem`、`POST /api/giftcards/recharge`、`GET /api/giftcards/user` |
| 对账 | 与支付/财务系统的对账报表、日终结算 |

## 4. 流程（未来规划）
1. **创建批次**
   1. 选择模板 → 设置数量、面额、渠道、有效期 → 生成卡号或导入 → 审批 → 激活。
   2. 可与供应商/合作伙伴协同（代发）。
2. **发放/兑换**
   1. 通过活动、积分、手动发放、API 发放；记录来源。
   2. 客户收到卡号/二维码，激活后可在订单中使用或转赠。
3. **消费/核销**
   1. 订单支付选择礼品卡 → 系统校验余额/限制 → 扣减 → 记录交易 → 通知客户。
4. **对账/退款**
   1. 日终汇总卡交易，与财务系统对账。
   2. 退货可退回原卡（余额增加）或生成新卡。

## 5. 数据 & API
### 当前阶段（MVP）
- **表**：`order_benefit_reviews`（订单侧审核记录）。
- **API**：
  - `GET /admin/orders/:id/benefit-reviews`
  - `POST /admin/orders/:id/benefit-reviews`
  - `POST /admin/orders/benefit-reviews/approve`
  - `POST /admin/orders/benefit-reviews/reject`
  - `GET /admin/orders/benefit-codes`（最小校验，后续接礼品卡系统）
### 未来规划
- **表**：`giftcard_templates`、`giftcard_batches`、`giftcards`、`giftcard_transactions`、`giftcard_audit_logs`、`giftcard_risk_events`。
- **API**：
  - `GET /api/giftcards/templates`、`POST /api/giftcards/templates`。
  - `POST /api/giftcards/templates/{id}/batches`、`POST /api/giftcards/batches/{id}/activate`。
  - `POST /api/giftcards/issue`、`POST /api/giftcards/recharge`、`POST /api/giftcards/redeem`、`POST /api/giftcards/refund`。
  - `GET /api/giftcards/{id}`、`GET /api/giftcards/user`。

## 6. 权限与审计
- 权限：`giftcard.read`、`giftcard.manage`、`giftcard.issue`、`giftcard.recharge`、`giftcard.approval`、`giftcard.reports`。
- 审计：发行、充值、消费、退款、作废、转赠等操作记录审计；卡号/卡密需加密存储并限制访问。
> MVP 仅使用订单审核权限与事件日志记录。

## 7. KPI（未来规划）
| 指标 | 目标 |
| --- | --- |
| 卡使用率 | ≥ 70% |
| 异常拦截率 | ≥ 98% |
| 充值/消费延迟 | < 1 秒 |
| 对账准确率 | 100% |

## 8. 风险（未来规划）
- 礼品卡属于储值业务，可能涉及监管（预付卡许可）；需与法务确认。
- 卡密泄露、批量盗刷风险，需要加密与风控。
- 多渠道使用需确保同步与限额一致。

- AI 风控与自动冻结/解冻策略。
