# 阶梯价 & 客户专属价 PRD

> 覆盖页面：`web-admin/app/pages/pricing/rules.vue` 中的阶梯价、客户价配置区，及在 SKU/客户/渠道详情引用的定价规则组件。该模块是 pricebook 的规则层，用于根据数量、客户属性、渠道等条件动态调整价格。

## 1. 背景与目标
- 普通价目表难以覆盖复杂场景（批量折扣、会员价、特定客户价）。
- 需要配置化的规则引擎来维护阶梯价、客户专属价，并与价格查询 API、订单、促销联动。
- **与其他模块区别**：阶梯价/客户价是在“定价层”处理基础价的条件化调整，通常在 pricebook 之后、促销/优惠券之前执行；促销规则/优惠券/礼品卡属于营销权益层（可叠加额外优惠或福利），两者需在执行顺序、可叠加性上明确策略。

**目标**
1. 建立统一的定价规则模型：条件（Condition）+ 动作（Action），支持阶梯、折扣、固定价、价差。
2. 支持客户级别、客户组、会员等级、渠道、区域、订单量等条件组合；可输出最终价或叠加折扣。
3. 提供冲突检测、优先级、模拟、审批能力。

## 2. 角色
| 角色 | 价值 |
| --- | --- |
| 定价经理 | 灵活配置阶梯/客户价，避免手工维护大量 pricebook | 
| 渠道/销售 | 为客户创建或申请专属价，快速响应谈判 |
| 订单系统 | 查询规则，实时给出应付价 |
| 财务/合规 | 审核特殊折扣，防止越权 |

## 3. 信息架构
1. **规则列表**
   - 字段：名称、类型（阶梯/客户价）、适用范围（SKU/类目）、条件摘要、折扣动作、优先级、状态、有效期。
   - 筛选：类型、状态、创建人、适用渠道/客户。
2. **规则编辑器**
   - 条件构建器：
     - 客户维度：客户 ID、客户组、会员等级、供应商、区域、门店。
     - 订单维度：购买数量、订单金额、时间段、渠道、终端类型。
     - 商品维度：SKU、类目、品牌、标签。
   - 动作配置：固定价、折扣（%）、价差、免邮、积分加成等；可定义阶梯（数量/金额区间）。
   - 优先级 & 冲突策略：显式设置 priority，确定与 pricebook 的叠加/覆盖关系。
   - 审批与有效期：默认草稿 → 审批 → 生效；支持定时生效、提前终止。
3. **模拟器**
   - 输入 SKU、客户、渠道、数量、时间 → 输出匹配的规则及最终价格，供测试与运营使用。

## 4. 功能清单
| 功能 | 描述 |
| --- | --- |
| 阶梯价 | 基于数量/金额区间设置不同折扣/最终价；支持 up/down price、累进/非累进 |
| 客户专属价 | 针对指定客户或客户组设定固定价或折扣 |
| 规则版本 | 历史版本 & 回滚；复制规则 |
| 冲突检测 | 同一 SKU + 客户/渠道 的多个规则冲突时提醒；提供决策策略（最高优先级 / 最低价 / 最近生效） |
| 审批 | 高折扣或客户专属价需审批；记录特批原因 |
| API 接口 | `POST /api/pricing/rules/query`，供订单系统实时获取结果（传入上下文） |
| 日志与审计 | 每次触发规则可记录（可选）供分析；配置变动写入审计 |

## 5. 流程
1. **创建阶梯价**
   1. 选择 SKU/类目 → 定义条件（渠道、客户组、时间） → 配置阶梯区间与折扣。
   2. 设置优先级与冲突策略；提交审批。
   3. 审批通过后生效，系统自动推送到价格查询服务。
2. **客户专属价**
   1. 销售在客户详情或规则页面发起申请 → 填写价格、有效期、原因。
   2. 触发审批（销售主管 → 定价经理 → 财务）。
   3. 生效后绑定到客户，订单查询时优先返回专属价。
3. **模拟与测试**
   1. 运营输入 SKU、客户、渠道、数量 → 运行模拟。
   2. 系统显示命中的规则、计算步骤、最终价，便于校验。

## 6. 数据 & API
- **表**：`pricing_rules`、`pricing_rule_conditions`、`pricing_rule_actions`、`pricing_rule_versions`、`pricing_rule_audit_logs`、`pricing_rule_metrics`。
- **API**：
  - `GET /api/pricing/rules`、`POST /api/pricing/rules`、`PATCH /api/pricing/rules/{id}`、`POST /api/pricing/rules/{id}/publish`、`POST /api/pricing/rules/{id}/simulate`。
  - `POST /api/pricing/rules/query`（输入上下文，返回价格/折扣明细）。

## 7. 权限
- `pricing.rule.read`、`pricing.rule.manage`、`pricing.rule.approval`、`pricing.rule.simulate`。
- 审计：规则变动、审批、发布记录 `admin_console_audit_events`。

## 8. KPI
| 指标 | 目标 |
| --- | --- |
| 规则审批周期 | ≤ 2 天 |
| 冲突率 | < 1% |
| 查询 SLA | API 99% < 200ms |
| 特批记录率 | 100%（每条客户专属价有审批记录） |

## 9. 风险
- 规则数量多导致性能问题，需缓存/预编译。
- 冲突策略不清会导致价格错误，必须提供可视化冲突检测。
- 规则与 pricebook 同时作用，需要明确叠加顺序与优先级。

## 10. Backlog
- 规则分组/继承：按渠道/地区复用。
- AI 推荐折扣：基于库存、竞品、GMV 推荐合适折扣。
- 规则可视化：以流程/树图显示匹配路径。
- 实时分析：统计命中率、最常用规则、收益影响。
