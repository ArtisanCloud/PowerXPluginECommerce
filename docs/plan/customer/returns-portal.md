# 客户自助退换货门户 PRD

> 覆盖后台配置页面：`/customer/returns/management/**`、`/customer/returns/process/**`、`/customer/returns/config.vue`、`/customer/returns/notifications/**`，以及计划中的 C 端自助门户（H5 / Web）入口。

## 1. 背景与目标
- 当前后台可配置售后流程，但缺乏面向客户的自助入口，导致客服压力大、效率低。
- 电商插件需提供完整的退换货体验：客户自助发起、后台审批、仓储收货、退款结算。

**目标**
1. 搭建可品牌化的自助门户（Web/H5/小程序嵌入），支持扫码或订单详情直接跳转。
2. 后台提供流程模板、SLA、通知、规则配置，并与订单、库存、结算模块打通。
3. 实现端到端透明追踪：客户随时查看进度、物流、退款状态；后台实时掌控负载。

## 2. 用户与角色
| 角色 | 需求 |
| --- | --- |
| 终端客户 | 快速申请、上传凭证、跟踪售后进展、收到退款/补发 |
| 客服/售后 | 审核申请、沟通客户、修改方案、升级处理 |
| 仓储/物流 | 收货质检、异常反馈、发出换货或补发 |
| 财务 | 审核退款、对账、发起打款 |
| 运营 | 配置策略、统计售后原因、优化流程 |

## 3. 信息架构
1. **后台配置中心**
   - **流程配置 (`process`)**：节点（申请→审核→寄回→质检→处理→退款/换货）、SLA、条件分支、升级策略。
   - **策略配置 (`management`)**：售后类型（仅退款/退货退款/换货/补发）、支持渠道、可申请时间窗口、黑名单。
   - **通知模板 (`notifications`)**：邮件、短信、站内、Webhook 模板；针对各节点提供变量。
   - **表单配置**：自助门户表单字段（订单号、SKU、数量、原因、凭证、图片）。
2. **自助门户（需新建前台项目或复用 Nuxt 页面）**
   - 登录 / 验证：订单号 + 手机号、账号登录、魔法链接。
   - 申请流程：选择订单 → 选择商品 → 选择售后类型 → 填写信息 → 上传凭证 → 确认。
   - 进度跟踪：显示节点、处理人、物流信息、退款状态；可补充资料、撤销申请。
   - 客户互动：内嵌 IM / 消息、FAQ、自动化建议。
3. **后台工单处理**
   - 工作台：待处理售后、优先级、SLA 倒计时。
   - 详情页：客户信息、订单、商品、证据、沟通记录、历史处理。
   - 操作：审批、修改方案、生成退货单、指派仓库、发起退款。

## 4. 功能清单
| 模块 | 功能 | 说明 |
| --- | --- | --- |
| 入口配置 | 订单页按钮、邮件/短信链接、公众号菜单 | 支持不同渠道入口，统一 OAuth 与风控 |
| 表单引擎 | 字段配置、条件展示、上传控件、校验 | 支持多语言、多品牌样式 |
| SLA 配置 | 节点时限、超时提醒、升级策略 | 与 `settings/orders.vue` 共享配置底座 |
| 审批流 | 自动/人工审核、工作量分配 | 支持机器人优先审核简单场景 |
| 物流联动 | 退货地址、运费模板、面单生成、轨迹查询 | 调用 `shipping/**` 模块接口 |
| 仓储操作 | 质检、验货、差异处理 | 更新库存状态、触发补发/重发 |
| 退款结算 | 自动/手动退款、礼品卡补偿、积分返还 | 与 `payments/providers.vue`、`settlements.vue` 关联 |
| 通知中心 | 多渠道通知、状态订阅、Webhook | 面向客户与内部成员 |
| 报表与分析 | 售后率、原因、渠道分布、SLA 达成率 | 支持导出 & Dashboard |
| 自助升级 | 客户可申请升级 / 申诉，自动分派主管 |

## 5. 核心流程
1. **客户发起申请**
   1. 入口：订单详情→点击“申请售后”或扫描包裹内二维码。
   2. 验证身份（登录/验证码），选择订单/商品/数量。
   3. 选择售后类型、原因，上传凭证。
   4. 系统校验（是否超期、黑名单、订单状态），自动给出建议。
   5. 提交后生成售后单，客户收到确认通知。
2. **后台审核**
   1. 工单进入待审核队列，按照技能/优先级分配给客服。
   2. 客服查看证据、可以与客户沟通，必要时要求补充资料。
   3. 决策：同意退货/退款/换货或拒绝；可配置自动通过（低金额）。
   4. 系统触发后续节点（生成退货单、通知仓库、预约物流等）。
3. **物流与质检**
   1. 客户寄回或上门取件；系统生成运单，提供跟踪。
   2. 仓库收货后质检 → 记录结果（合格/不合格/部分）。
   3. 根据质检结果执行退款、换货或补发；异常情况下升级。
4. **退款 / 补偿**
   1. 触发支付渠道退款，或发放礼品卡/积分；记录交易流水。
   2. 财务审核→执行→回写售后单状态。
5. **闭环与评价**
   1. 售后完成后，客户收到通知并可评价服务。
   2. 数据写入分析模块，供运营优化策略。

## 6. 数据与接口
- **表**：`after_sales_requests`、`after_sales_items`、`after_sales_logs`、`after_sales_tasks`、`after_sales_sla`、`after_sales_notifications`、`after_sales_refunds`。
- **API（示例）**：
  - `POST /api/after-sales/apply`（前台提交）
  - `GET /api/after-sales/{id}`、`PATCH /api/after-sales/{id}`（后台处理）
  - `POST /api/after-sales/{id}/approve`、`POST /api/after-sales/{id}/reject`
  - `POST /api/after-sales/{id}/logistics`（创建退货运单）
  - `POST /api/after-sales/{id}/refund`
  - `GET /api/after-sales/settings`、`POST /api/after-sales/settings`
  - `POST /api/after-sales/webhook`（状态变更通知）

## 7. 权限、风控、审计
- 权限项：`afterSales.read`、`afterSales.manage`、`afterSales.config`、`afterSales.refund`、`afterSales.audit`。
- 风控：
  - 黑名单客户限制自助申请；
  - 单日申请次数限制；
  - 异常原因（频繁退货、假冒）自动警报。
- 审计：所有节点操作（审批、质检、退款）写入审计日志，记录前后状态、操作者、时间。

## 8. KPI / 度量
| 指标 | 目标 |
| --- | --- |
| 自助受理率 | ≥ 70% 售后通过自助入口完成 |
| SLA 达成率 | ≥ 95% 节点在时限内处理 |
| 客诉率 | 售后相关投诉下降 30% |
| 客户满意度 (CSAT) | ≥ 4.5 / 5 |
| 重复申请率 | 异常重复申请 < 3% |

## 9. 依赖与风险
- 依赖订单、仓储、支付、库存、营销券模块提供数据与操作接口。
- 自助门户需要统一身份认证，与前台账号系统打通。
- 物流对接需支持多承运商、面单生成、轨迹回调。
- 退款资金占用，需要财务和支付渠道配合，可能涉及税务。
- 跨境/多地区需考虑本地法规、取件方式、语言多样化。

## 10. Backlog
- 客户端 SDK/组件：提供可嵌入小程序/APP 的售后组件。
- AI 帮助：自动识别凭证图像、给出初步判定，减少人工审核压力。
- 退货即刻退款：与风控联动，对低风险订单提前退款。
- 售后知识库：根据原因自动推荐解决方案或 FAQ。
- 供应商协同：允许供应商登录处理代发订单的售后。
