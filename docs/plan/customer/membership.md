# 会员等级（菜单：会员登记）PRD

> 覆盖路径：`/customer/membership/tiers`、`/customer/membership/benefits`、`/customer/membership/rules` 以及相关弹窗/模态。

## 1. 背景与目标
- 会员等级体系是客户运营闭环的核心，决定权益包、成长路径、保级策略。
- 现有 Nuxt 页面提供静态示例，需要明确产品化能力（配置、规则、洞察、联动）。

**目标**
1. 让运营能够自助配置等级、权益、升级/降级规则。
2. 与积分、成长值、营销券包联动，形成激励闭环。
3. 提供可观察的数据（等级分布、保级率、权益使用率）。

## 2. 用户与角色
| 角色 | 诉求 |
| --- | --- |
| CRM 运营 | 快速配置等级与权益，测试策略，实时发布 |
| 营销/增长 | 连接券包、任务，引导会员升级 |
| 财务/合规 | 审核成本，确保权益发放受控 |
| 技术运营 | 监控成长值计算、任务执行、审计记录 |

## 3. 信息架构
1. **等级配置（tiers.vue）**
   - 列表：等级名称、顺序/权重、成长值门槛、有效期、权益包、状态。
   - 操作：新增、编辑、复制、上下线、排序。
   - 预览：模拟不同场景（新客、老客）升级路径。
2. **权益包配置（benefits.vue & benefits/**）**
   - 权益类型：包邮券、积分加速、专属客服、生日礼等。
   - 配置项：发放方式（自动/手动）、频率、库存、成本预算。
   - 可绑定多个等级，支持差异化显示。
3. **规则中心（rules.vue）**
   - 升级/降级条件：累计成长值、周期消费次数、任务完成。
   - 特殊规则：邀请好友、节日活动、黑名单（禁止升级）。
   - 支持测试/模拟：输入客户指标，显示等级变化。
4. **分析视图（analytics/**）**
   - 指标：等级分布、晋升率、降级率、权益使用率、贡献 GMV。
   - 看板：趋势图、Top 客户、预警（保级失败占比高）。

## 4. 功能列表
| 模块 | 功能 | 说明 |
| --- | --- | --- |
| 等级列表 | CRUD、排序、启停 | 需校验成长值区间、冻结中不可启用 |
| 等级详情 | 展示门槛、权益、当前人数 | 支持导出名单、跳转至客户列表筛选 |
| 权益管理 | 权益库、分配、库存/预算 | 接入营销券、“积分商城”商品、外部福利 |
| 规则引擎 | 条件配置、优先级、测试 | 表单 + DSL（JSON），支持版本回滚 |
| 批量操作 | 批量调整等级、补发权益 | 需审批 & 审计 |
| 分析 | 分布、趋势、异常预警 | 接入 BI 或实时指标 API |

## 5. 交互流程
1. **新增等级**
   1. 运营点击“新增等级” → 弹窗输入基础信息（名称、代码、描述、顺序）。
   2. 配置成长值/消费门槛、有效期（永久/周期/保级规则）。
   3. 选择权益包并设定权益参数（发放频次、数量）。
   4. 保存后进入“草稿”状态，可预览并提交审批；审批通过后上线。
2. **权益配置**
   1. 进入权益库 → 选择权益类型 → 填写参数。
   2. 关联等级（多选），并配置生效时间、库存预警阈值。
   3. 创建成功后生成权益 ID，可在等级详情查看。
3. **规则发布**
   1. 在规则中心选择“升级/降级”规则 → 使用可视化表单配置条件。
   2. 提交后生成 DSL JSON，存储于规则引擎表。
   3. 支持“模拟”输入（客户成长值、消费次数）验证结果。

## 6. 数据与接口
- **核心表**：`membership_tiers`、`membership_benefits`、`membership_rules`、`membership_assignments`、`membership_audit_logs`。
- **API（示例）**：
  - `GET /api/membership/tiers`、`POST /api/membership/tiers`、`PATCH /api/membership/tiers/{id}`、`POST /api/membership/tiers/{id}/publish`。
  - `GET /api/membership/benefits`、`POST /api/membership/benefits`。
  - `POST /api/membership/rules`、`POST /api/membership/rules/simulate`。
  - `POST /api/membership/tiers/{id}/bulk-adjust`（批量调整客户等级）。

## 7. 权限与审计
- 权限项：`membership.read`、`membership.manage`、`membership.publish`、`membership.benefit.manage`、`membership.rule.manage`。
- 所有配置变更均写入 `admin_console_audit_events`，记录旧值/新值、审批信息。
- 批量等级调整需审批流程 + 成本评估（如发放权益）。

## 8. KPI / 成功标准
| 指标 | 目标 |
| --- | --- |
| 等级配置上线时间 | 新等级审批后 1 小时内生效 |
| 权益发放准确率 | ≥ 99.5%，异常自动告警 |
| 保级提醒命中率 | ≥ 80% 即将降级会员收到提醒 |
| 审计覆盖率 | 100% 配置变更可追踪 |

## 9. 风险与依赖
- 依赖积分、成长值服务提供实时数据；需确保事件一致性。
- 权益发放涉及库存/成本，需要与营销、财务确认额度。
- 复杂规则可能造成性能压力，建议引入规则引擎或分布式任务。
- 上线/下线需考虑对现有会员的影响，提供迁移策略。

## 10. Backlog
- 会员等级 A/B 测试：不同策略对比转化率。
- 与营销自动化联动：根据等级变化触发旅程。
- 会员权益 API：开放给前台（自助门户）实时查询。
- 成长值可视化：在 `customer/members.vue` 中展示升级路径图。
