# 商品（SPU）管理 PRD

> 适用页面：`web-admin/app/pages/product/spus/**`、`product/index.vue` 中的商品概览卡片、以及相关模态（创建/编辑/发布、批量导入导出）。

## 1. 背景与目标
- SPU 是商品中心的核心实体，承载跨渠道、跨 SKU 的基础信息与生命周期。
- 当前页面提供基本 CRUD UI，需要明确业务能力：多语言、多渠道、版本管理、审批、批量工具。

**目标**
1. 让商品运营能快速创建/复制/上线商品，支持草稿→审核→发布全过程。
2. 与 SKU、定价、渠道、库存联动，保证数据一致、可追踪。
3. 提供批量导入导出、模板、版本回滚、审计功能，支撑大规模运营。

## 2. 用户与角色
| 角色 | 诉求 |
| --- | --- |
| 商品运营 | 高效录入、维护商品，控制上下架和版本 |
| 渠道运营 | 查看商品状态、设置渠道可见性、触发上架任务 |
| 品控/法务 | 审核内容、资质，确保合规上线 |
| 数据/开发 | 通过 API 获取标准化商品数据，用于前台或第三方渠道 |

## 3. 信息架构
1. **商品列表 (`spus/index.vue`)**
   - 列字段：SPU 编码、名称、商品类型（一次性/订阅）、多语言标题、品类、品牌、状态、渠道覆盖、更新时间、负责人。
   - 筛选：类目、品牌、状态（草稿/审核中/已发布/下架）、负责人、渠道、商品类型、更新时间、标签。
   - 批量操作：导入/导出、批量发布/下架、指派责任人、添加标签。
2. **商品详情/编辑 (`spus/edit/**`)**
   - Tab：基础信息、属性、媒体、内容（描述、富文本、多语言）、销售渠道、关联 SKU、**订阅计划配置（如适用：周期、价格、试用期、自动续费、取消策略）**、供应商、合规资料。
   - 版本管理：查看历史版本、差异、回滚；支持在发布前预览。
   - 状态控制：草稿 → 提交审核 → 审核通过发布，或驳回。
3. **创建向导 (`spus/create.vue`)**
   - 步骤：选择类目/模板 → **选择商品类型（一次性 / 订阅 / 组合）** → 填写基础信息 → 上传媒体 → 配置属性/规格 → 定义渠道与发布计划。
   - 模板：可根据类目套用表单字段、默认属性。
   - 订阅型商品附加步骤：配置订阅计划（计划名称、计费周期：月/季/年/自定义天数、价格、试用期、自动续费策略、取消/续订规则、是否允许多计划绑定同一 SPU）。
4. **商品概览 (`product/index.vue`)**
   - 指标卡：在售商品数、待审核商品、下架商品、渠道覆盖。
   - 快捷入口：新建商品、批量导入、查看最近更新。

## 4. 功能清单
| 功能 | 描述 |
| --- | --- |
| 草稿/版本管理 | 保存草稿、提交审核、记录版本、支持回滚 |
| 审批流 | 多级审批（商品运营→品控→法务），可配置 SLA |
| 多语言支持 | 标题、描述、属性值多语言，支持复制、批量翻译 |
| 渠道可见性 | 针对不同渠道配置可售状态、上架时间、内容差异 |
| SKU 关联 | 在 SPU 中查看/批量创建 SKU，自动继承属性/规格 |
| 媒体管理 | 绑定图片/视频/3D 模型，设置主图、渠道适配规则 |
| 合规资料 | 上传证照、合规文档，记录有效期、提醒 |
| 批量工具 | 导入模板、导出 CSV/Excel、批量复制 | 
| 标签与搜索 | 自定义标签、关键字，支持高级搜索 |
| 订阅/周期性配置 | 为订阅型商品配置多个订阅计划（周期、价格、试用期、自动续费、取消策略、代扣设置），与定价/支付模块联动 |
| 审计日志 | 记录所有变更（字段、版本、审批意见） |

## 5. 关键流程
1. **新建商品**
   1. 运营在列表点击“创建 SPU” → 选择类目/模板。
   2. 按步骤填写信息；可以保存草稿。
   3. 完成后提交审核 → 审批通过即发布，推送到渠道。
2. **批量导入**
   1. 下载导入模板（按类目/渠道） → 填写 Excel → 上传。
   2. 系统校验字段、类目、SKU 唯一性 → 生成任务。
   3. 大量数据需审批或分批执行；完成后出报告。
3. **版本管理**
   1. 编辑商品 → 保存新版本（草稿）。
   2. 可查看差异（字段对比）、预览；选择发布版本。
   3. 支持回滚到旧版本，并记录审计。
4. **渠道上架**
   1. 在 SPU 中配置可售渠道、上架时间、内容差异。
   2. 发布后触发 `channels/publishing` 的任务，推送到外部渠道。
   3. 若某渠道审核未通过，显示返回信息，可更新后再次推送。
5. **下架/重上架**
   1. 运营批量选择 SPU → 设置下架计划（立即/定时）。
   2. 同步通知库存、渠道、营销，触发相关操作。
6. **订阅计划维护**
   1. 在订阅型 SPU 详情中新增/编辑订阅计划（周期、价格、续费策略）。
   2. 更新计划后同步到定价中心、支付单元（自动扣费、代扣授权）与渠道；如需立即生效，触发审批与版本发布。

## 6. 数据 & API
- **表**：`product_spus`、`product_spu_versions`、`product_spu_locales`、`product_spu_channels`、`product_spu_tags`、`product_spu_subscription_plans`（订阅计划：周期、价格、试用期、自动续费设置）、`product_spu_audit_logs`。
- **API（示例）**：
  - `GET /api/products/spus`、`POST /api/products/spus`、`PATCH /api/products/spus/{id}`、`DELETE /api/products/spus/{id}`。
  - `POST /api/products/spus/{id}/submit`（提交审核）、`POST /api/products/spus/{id}/publish`、`POST /api/products/spus/{id}/withdraw`。
  ￼- `POST /api/products/spus/import`、`POST /api/products/spus/export`。
  - `GET /api/products/spus/{id}/versions`、`POST /api/products/spus/{id}/versions/{versionId}/restore`。
  - `POST /api/products/spus/{id}/channels`（配置渠道）。

## 7. 权限 & 审计
- 权限项：`product.spu.read`、`product.spu.manage`、`product.spu.publish`、`product.spu.import`、`product.spu.audit`。
- 审计：保存草稿、提交、发布、下架、导入导出、渠道推送都要记录操作人、字段变更、审批链；写入 `admin_console_audit_events`。

## 8. KPI / 度量
| 指标 | 目标 |
| --- | --- |
| 创建到上线时长 | ≤ 2 天（含审批） |
| 审批 SLA 达成率 | ≥ 95% |
| 批量导入成功率 | ≥ 99%（其余提供清晰错误报告） |
| 渠道同步成功率 | ≥ 98% |
| 审计覆盖率 | 100% |

## 9. 依赖与风险
- 依赖类目、属性、媒体、供应商等基础模块提供数据。
- 与渠道、库存、营销存在强关联：发布/下架需触发多个系统，需设计异步任务与幂等。
- 多语言 & 模板可能导致表单复杂，需要良好 UX 与校验。
- 法务/品控审批要与公司的审批中心对接，避免重复建设。

## 10. Backlog
- AI 辅助：根据类目自动生成商品卖点、文案、图片建议。
- 内容校验：敏感词、合规检查自动化。
- 商品包 / 组合销售配置。
- API Key：开放标准化商品 API 给合作伙伴。
- 与供应商 Portal 对接：供应商可直接提交商品草稿。
