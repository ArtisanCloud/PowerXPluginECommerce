# 品牌管理 PRD

> 适用页面：`web-admin/app/pages/product/brands.vue`、品牌相关弹窗/模态，以及后台 `backend/internal/services/product/brand` API。

## 1. 背景与目标
- 品牌作为商品中心的重要维度，影响前台展示、渠道上架、合规审核与供应链协同。目前仅有基础表单示例，缺乏品牌生命周期、资质审核、与供应商/渠道联动的能力。

**目标**
1. 建立品牌档案库，支持多维度信息（基本信息、授权、资质、媒体、渠道策略）。
2. 提供品牌上线/下线、审核、资质到期提醒等全流程管控。
3. 与 SPU/SKU、供应商、营销等模块打通，让品牌成为统一引用实体。

## 2. 用户与角色
| 角色 | 诉求 |
| --- | --- |
| 商品运营 | 录入/维护品牌信息、授权范围、绑定商品 |
| 品控/法务 | 审核品牌资质、合同、到期提醒 |
| 渠道运营 | 配置各渠道的品牌上架策略、品牌馆内容 |
| 供应链/采购 | 管理品牌供应商、合作等级、价格策略 |
| 营销 | 获取品牌素材、故事、标签，用于活动与推广 |

## 3. 信息架构
1. **品牌列表 (`brands.vue`)**
   - 列字段：品牌名称（中/英）、简称、品牌级别、所属公司、状态（草稿/审核中/启用/停用）、主要品类、授权有效期、负责人、更新时间。
   - 筛选：状态、授权到期时间、品类、渠道、审批状态、标签。
   - 批量操作：启用/停用、指派负责人、导出、发起资质更新。
2. **品牌详情**
   - Tab：基础信息（名称、LOGO、描述、多语言）、品牌故事/定位、授权信息（授权方、合同号、有效期、授权区域、授权品类）、资质与证照、渠道策略、供应商关联、媒体素材、审批记录。
   - 支持上传 LOGO、主视觉、品牌规范 PDF。
3. **品牌创建/编辑流程**
   - 步骤：基础信息 → 品牌授权 → 资质与证照 → 渠道策略 → 审核提交。
   - 支持草稿保存，多语言内容同步。
4. **渠道品牌馆配置**
   - 针对特定渠道，配置品牌展示内容、主推商品、Banner、SEO 字段。

## 4. 功能清单
| 功能 | 描述 |
| --- | --- |
| 品牌档案 | 基础信息、多语言描述、LOGO/媒体、品牌故事 |
| 授权管理 | 记录授权方、合同、有效期、覆盖区域/品类，自动提醒到期 |
| 审批流 | 品牌创建/修改需经过品控/法务审批，支持多级配置 |
| 渠道配置 | 设置品牌在不同渠道的状态、优先级、展示内容 |
| 供应商关联 | 绑定授权供应商、合作等级、主要联系人 |
| 合规资料 | 上传证照、商标注册、质检报告，支持有效期提醒 |
| 标签/分类 | 品牌级别（自有/代理/合作）、风格标签、市场区域 |
| 批量导入导出 | Excel 模板导入品牌档案，导出给渠道或 BI |
| 审计日志 | 记录品牌信息变化、审批意见、授权更新 |
| 通知提醒 | 授权/证照到期、渠道异常、审批待处理等通知 |

## 5. 关键流程
1. **创建品牌**
   1. 商品运营点击“新建品牌” → 填写基础信息、上传 LOGO、选择品牌级别。
   2. 填写授权信息、上传合同/证照，设置有效期。
   3. 配置渠道策略、品牌故事 → 提交审批。
   4. 品控/法务审核 → 通过后品牌状态改为启用，可供 SPU/SKU 选择。
2. **品牌资质更新**
   1. 系统根据有效期提前提醒 → 运营发起“资质更新”任务。
   2. 上传新证照/合同 → 审批通过，更新有效期记录。
3. **渠道品牌馆配置**
   1. 在品牌详情选择渠道 tab → 配置展示内容、主推 Product List、Banner。
   2. 提交后生成渠道同步任务，推送到 `channels/publishing`。
4. **品牌停用/下线**
   1. 针对违规或到期品牌，运营可发起停用，需说明原因。
   2. 停用通知关联的商品和渠道，要求处理后再允许重新启用。

## 6. 数据 & API
- **表**：`product_brands`、`product_brand_locales`、`product_brand_licenses`、`product_brand_media`、`product_brand_channels`、`product_brand_suppliers`、`product_brand_audit_logs`、`product_brand_tags`。
- **API（示例）**：
  - `GET /api/products/brands`、`POST /api/products/brands`、`PATCH /api/products/brands/{id}`、`PATCH /api/products/brands/{id}/status`。
  - `POST /api/products/brands/{id}/submit`（提交审核）、`POST /api/products/brands/{id}/approve`、`POST /api/products/brands/{id}/reject`。
  - `POST /api/products/brands/{id}/licenses`、`POST /api/products/brands/{id}/channels`、`POST /api/products/brands/{id}/suppliers`。
  - `POST /api/products/brands/import`、`POST /api/products/brands/export`。
  - `GET /api/products/brands/{id}/audit`。

## 7. 权限与审计
- 权限：`product.brand.read`、`product.brand.manage`、`product.brand.approve`、`product.brand.channel`、`product.brand.import`。
- 审计：品牌创建/修改、授权上传、渠道配置、审批、导入导出等操作写入 `admin_console_audit_events`，在品牌详情展示最近操作记录。

## 8. KPI / 度量
| 指标 | 目标 |
| --- | --- |
| 品牌审批完成周期 | ≤ 3 个工作日 |
| 授权到期提醒覆盖率 | 100%，提前 30 天提醒 |
| 品牌资料完整率 | ≥ 95%（基础信息+授权+媒体） |
| 渠道同步成功率 | ≥ 98% |
| 违规/停用响应时长 | 24 h 内完成停用或整改方案 |

## 9. 依赖与风险
- 依赖供应商模块获取授权供应商信息；需保证数据一致。
- 与 SPU/SKU、渠道、营销紧耦合：品牌停用需同步到所有关联实体，需设计事务/任务机制。
- 审批与证照涉及法务流程，需与公司审批中心/合同系统集成。
- 资质文件涉及隐私/合规，需存储加密、访问控制。
- 多语言品牌内容要与 CMS/前台保持一致，避免重复维护。

## 10. Backlog
- 品牌评分体系：综合销量、退货率、渠道表现。
- 合作伙伴门户：供应商可在线更新品牌资质。
- 品牌故事模板：支持图文、视频、3D 展示。
- 品牌营销资源中心：集中管理海报、素材、活动包。
- AI 审核：自动校验品牌素材、识别合规风险。
