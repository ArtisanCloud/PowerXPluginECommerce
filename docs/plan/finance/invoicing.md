# 发票与税票 PRD

> 覆盖尚未有页面的发票管理模块，涉及订单/结算中的开票、发票状态、税务合规、电子/纸质发票管理，与税率 PRD 对齐。

## 1. 目标
- 管理发票申请、开票、发送、归档，支持多地区税务需求（增值税专票/普票、电子发票），与结算、订单、税率数据同步。

## 2. 信息架构
- **发票列表**：发票编号、订单/结算单、客户/对象、类型（专票/普票/电子）、金额、税额、状态（申请/审核/开票/发送/作废）、开票日期、发票文件。
- **发票详情**：
  - 基础信息：抬头、税号、地址、银行、发票类型、票据编号。
  - 关联：订单、结算单、税率、开票人、审批记录。
  - 附件：电子发票 PDF/二维码、纸票扫描件。
  - 操作：开票、重开、作废、发送。
- **开票申请**：客户/渠道/供应商提交申请，填写抬头、税号、地址、发票类型。

## 3. 功能
| 功能 | 描述 |
| --- | --- |
| 开票申请 | 客户/渠道/供应商提交发票需求，支持审批流 |
| 开票流程 | 财务审核 → 开票（对接发票系统或导入）→ 上传票据 → 发送给客户 |
| 电子发票接口 | 对接第三方电子发票平台（如航信/百望）；或导入 PDF |
| 发票状态跟踪 | 显示状态、发票号码、发送记录、作废记录 |
| 抬头管理 | 保存客户抬头信息、税号、地址、银行；与 CRM 同步 |
| 税额校验 | 根据税率/税则自动计算税额，校验差异 |
| 审计 & 归档 | 记录操作，导出报表，支持税务稽查 |

## 4. 数据 & API
- 表：`invoices`、`invoice_requests`、`invoice_items`、`invoice_logs`、`invoice_documents`。
- API：`POST /api/invoices/requests`、`POST /api/invoices/{id}/issue`、`POST /api/invoices/{id}/send`、`POST /api/invoices/{id}/void`、`GET /api/invoices`。

## 5. 权限 & 审计
- 权限：`invoice.request`、`invoice.manage`、`invoice.issue`、`invoice.view`、`invoice.report`。
- 审计：申请、开票、发送、作废操作；附带票据、时间、人员。

## 6. KPI
| 指标 | 目标 |
| --- | --- |
| 开票时效 | ≤ 5 天 |
| 开票准确率 | ≥ 99% |
| 税务合规 | 100% |

## 7. 风险
- 税务政策差异；需与税率模块紧密联动。
- 发票信息敏感；需权限控制、加密。
- 系统对接中国电子发票等平台复杂；需 SDK/接口封装。

## 8. Backlog
- 客户自助开票入口（Portal）。
- 与 ERP/财务系统集成。
- AI 核对开票信息、防止错误。
